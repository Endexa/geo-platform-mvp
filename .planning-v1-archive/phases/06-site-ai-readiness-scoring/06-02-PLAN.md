  <action>
    Create `backend/app/services/scoring/crawlability_scorer.py`:
    - Import BaseScorer, ScoringCriterionResult from base_scorer
    - Import Playwright async API for SSR detection
    - Import httpx for TTFB measurement
    - Import urllib.robotparser for robots.txt parsing
    - Import loguru logger

    Class `CrawlabilityScorer(BaseScorer)`:

    `async def score_page(self, page_data: dict) -> list[ScoringCriterionResult]`:
    - page_data has keys: url, domain, html (raw HTML), crawl_data (CrawlResult dict from CrawlerService), main_content (text without JS)
    - Call each of the 12 criteria methods and collect results into a list
    - Return the list of 12 ScoringCriterionResults

    **Criteria C1-C8: AI bot access (BINARY)**
    - Method: `def _check_bot_access(self, bot_name: str, bot_field: str, criterion_id: str, crawl_data: dict) -> ScoringCriterionResult`
    - Read `crawl_data["ai_bot_access"][bot_field]` -- True=allowed (score 100), False=blocked (score 0), None=no directive (score 100, note "no specific directive found -- assumed allowed")
    - Apply to all 8 bots:
      - C1: GPTBot -> gptbot
      - C2: ClaudeBot -> claudebot
      - C3: PerplexityBot -> perplexitybot
      - C4: OAI-SearchBot -> Not in current AIBotAccess schema -- check robots.txt directly for "oai-searchbot" user-agent
      - C5: Claude-SearchBot -> claude_searchbot
      - C6: Bingbot -> Not in current AIBotAccess schema -- check robots.txt directly for "bingbot" user-agent
      - C7: CCBot -> ccbot
      - C8: Google-Extended -> google_extended
    - For C4 and C6 (not in AIBotAccess): use `_check_robots_txt_direct(url, user_agent)` helper that fetches and parses robots.txt for these specific bots. Cache the robots.txt content per domain to avoid re-fetching.
    - Human summary example: "GPTBot: ALLOWED -- ChatGPT can access and cite your content" or "GPTBot: BLOCKED via robots.txt -- ChatGPT cannot access your site"
    - Technical detail: Include the specific robots.txt line if blocked, or "No Disallow directive for GPTBot"

    **Criterion C9: SSR detection (GRADIENT)**
    - Method: `async def _check_ssr(self, url: str, no_js_content: str) -> ScoringCriterionResult`
    - Launch Playwright Chromium headless (one browser instance, reused across pages via `self._browser`)
    - Navigate to URL with `wait_until="networkidle"`, timeout=15000ms
    - Extract main content via JS: `document.querySelector('main') || document.querySelector('article') || document.querySelector('body')` -> `.innerText`
    - Compare JS content words vs no-JS content words (case-insensitive)
    - Overlap ratio = `len(no_js_words & js_words) / len(js_words)` if js_words else 1.0
    - Score = min(100, int(overlap * 100))
    - If Playwright fails: return score=50 with human_summary "Could not render page with JavaScript -- score uncertain"
    - Human summary: "{Excellent/Good/Poor} server-side rendering: {score}% of content available without JavaScript"
    - Technical detail: "JS-rendered words: {N}, No-JS words: {M}, Overlap: {X}%"
    - IMPORTANT: Per research pitfall #5, reuse ONE Playwright browser instance. Initialize in `__init__` as None, lazily create in first `_check_ssr` call. Close in `async def cleanup()`.

    **Criterion C10: Response time / TTFB (GRADIENT)**
    - Method: `async def _check_ttfb(self, url: str) -> ScoringCriterionResult`
    - Use httpx.AsyncClient to HEAD or GET the URL. Measure `response.elapsed` for TTFB.
    - Scoring: <500ms = 100, 500-1000ms linear scale 75-100, 1000-1500ms linear 50-75, 1500-3000ms linear 25-50, >3000ms = max(0, 25 - (ttfb-3000)/100)
    - On timeout/error: return _not_checked with reason
    - Human summary: "Page responds in {X}ms -- {Good/Acceptable/Slow/Very slow} for AI crawlers"

    **Criterion C11: HTTP status code (BINARY)**
    - Method: `async def _check_status_code(self, url: str) -> ScoringCriterionResult`
    - Send GET request with a GPTBot-like User-Agent header
    - Score: 200 = 100, 301/302 = 75 (redirect acceptable but not ideal), 403/404/5xx = 0
    - Human summary: "HTTP {status}: {explanation}"

    **Criterion C12: Resource blockage (GRADIENT)**
    - Method: `def _check_resource_blockage(self, crawl_data: dict) -> ScoringCriterionResult`
    - Check if robots.txt blocks CSS/JS resources (patterns like "Disallow: *.css" or "Disallow: *.js" or "Disallow: /static/" or "Disallow: /assets/")
    - This degrades rendering for bots that attempt partial rendering
    - Score: 100 if no resource blocks, 50 if some resources blocked, 0 if broad resource blocking
    - Use robots.txt raw content from crawl if available, or re-fetch
    - Human summary: "No resource blockage detected" or "CSS/JS resources blocked in robots.txt -- may degrade AI bot rendering"

    All criteria methods must follow the established pattern: return ScoringCriterionResult with all fields populated including evidence dict for drill-down.
