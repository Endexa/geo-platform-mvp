  <name>Task 1: Add custom query CRUD endpoints to audit API</name>
  <files>

  <action>
    **1. Add Pydantic schemas to `backend/app/schemas/audit.py`:**

    **CreateCustomQueryRequest** (inherits SecureBaseModel or BaseModel with `extra = "forbid"`):
    - `query_text: str = Field(..., min_length=10, max_length=500)` -- the query to ask AI engines
    - `category: str = Field(default="custom")` -- category label (default "custom", user can set to "industry", "brand_direct", etc.)

    **UpdateCustomQueryRequest** (same base):
    - `query_text: str | None = Field(None, min_length=10, max_length=500)`
    - `category: str | None = None`

    **CustomQueryResponse:**
    - `id: str`
    - `query_text: str`
    - `category: str`
    - `is_custom: bool`
    - `created_at: str`
    - Config: `from_attributes = True`

    **2. Add endpoints to `backend/app/api/audit.py`:**

    **`POST /api/v1/audit/{audit_id}/queries`** (auth required):
    - Depends: db, current_user
    - Verify audit exists and belongs to current_user
    - Create AuditQuery with:
      - `audit_id=audit_id`
      - `query_text=request.query_text`
      - `category=request.category`
      - `is_custom=True`
      - `is_editable=True`
    - db.add(), db.commit(), db.refresh()
    - Return CustomQueryResponse (201 Created)

    **`PUT /api/v1/audit/{audit_id}/queries/{query_id}`** (auth required):
    - Depends: db, current_user
    - Verify audit exists and belongs to current_user
    - Query AuditQuery by id, verify it belongs to this audit
    - Check `is_custom=True` -- only custom queries can be edited. Return 403 if not custom.
    - Update query_text and/or category if provided
    - db.commit(), db.refresh()
    - Return CustomQueryResponse

    **`DELETE /api/v1/audit/{audit_id}/queries/{query_id}`** (auth required):
    - Depends: db, current_user
    - Verify audit exists and belongs to current_user
    - Query AuditQuery by id, verify it belongs to this audit
    - Check `is_custom=True` -- only custom queries can be deleted. Return 403 if not custom.
    - Check if query has engine_responses -- if dispatched, prevent deletion (return 409 Conflict with message "Cannot delete a dispatched query. Re-run audit to include updated queries.")
    - db.delete(query), db.commit()
    - Return 204 No Content

    **`GET /api/v1/audit/{audit_id}/queries`** (auth required):
    - Depends: db, current_user
    - Verify audit exists and belongs to current_user
    - Query all AuditQuery records for audit, ordered by created_at
    - Return list of CustomQueryResponse (includes both auto and custom queries, distinguishable by is_custom flag)

    **Design decision:** Custom queries added AFTER an audit completes are stored in DB for the NEXT audit run. Adding/editing BEFORE dispatching includes them in the current run. This avoids mid-pipeline injection complexity (per Research open question 4).
  </action>

  <action>
    **1. Create `frontend/components/QueryEditor.vue`:**

    A component that displays all queries for an audit and allows CRUD on custom queries.

    **Props:**
    - `auditId: string` (required)
    - `queries: Array` (list of query objects from audit detail response)

    **Template structure:**
    - Section header "Queries" with count badge and "Add Custom Query" button
    - Query list showing each query as a card:
      - For auto-generated queries: display query_text, category badge (read-only)
      - For custom queries (is_custom=true): display query_text, category badge, edit button (PencilIcon), delete button (TrashIcon)
      - Visual distinction: custom queries have a dashed border or different background color (e.g., `bg-amber-50 border-amber-200`) and a "Custom" badge
    - "Add Custom Query" form (shown on button click):
      - Text input for query_text (min 10 chars, placeholder: "e.g., What are the best tools for...")
      - Category dropdown: "custom", "industry", "brand_direct", "comparison", "problem", "recommendation" (matching existing query categories)
      - Save and Cancel buttons
    - Edit mode: inline editing of query_text and category for custom queries
    - Delete confirmation: small confirm dialog before deletion

    **Emits:**
    - `@query-added` when a new custom query is created
    - `@query-updated` when a custom query is edited
    - `@query-deleted` when a custom query is removed

    **API calls** (using `useApiFetch` composable, same pattern as audit.vue):
    - POST `/api/v1/audit/${auditId}/queries` for adding
    - PUT `/api/v1/audit/${auditId}/queries/${queryId}` for editing
    - DELETE `/api/v1/audit/${auditId}/queries/${queryId}` for removing
    - Handle 403 (not custom) and 409 (already dispatched) errors with user-friendly messages

    **Styling:** Follow existing design system patterns from AuditResults.vue:
    - Cards use `class="card"` or equivalent Tailwind classes from the project
    - Buttons use `btn-primary` and `btn-secondary` classes
    - Icons from `@heroicons/vue/24/outline`: PlusIcon, PencilIcon, TrashIcon
    - Responsive: single column on mobile, content fits in the audit page layout

    **2. Modify `frontend/pages/audit.vue`:**

    - Import QueryEditor component
    - Add QueryEditor below the AuditResults component (or within it, in a new section after the query list)
    - Pass `auditId` and `queries` from the audit detail response to QueryEditor
    - On `@query-added`, `@query-updated`, `@query-deleted` events, refresh the audit detail data (re-fetch from API)
    - QueryEditor should be visible when audit is in COMPLETED status (user adding queries for next run) or PENDING status (user adding queries before first dispatch)
