Create `backend/app/services/dispatch_service.py` implementing the DispatchService class. This is the core business logic for Phase 3.

**ENGINE_CONFIG dict** at module level:
```python
ENGINE_CONFIG = {
    "openai": {
        "model_setting": "DISPATCH_MODEL_OPENAI",
        "provider": "openai",
    },
    "anthropic": {
        "model_setting": "DISPATCH_MODEL_ANTHROPIC",
        "provider": "anthropic",
    },
    "perplexity": {
        "model_setting": "DISPATCH_MODEL_PERPLEXITY",
        "provider": "perplexity",
    },
}
```
Read actual model names from settings at runtime (not hardcoded) so they are configurable.

**DispatchService class** with `__init__(self, db: Session)`:

**Method: `dispatch_all_queries(self, audit_id: UUID, queries: list[AuditQuery]) -> DispatchResult`**
- Iterates through queries, dispatching each to all three engines
- Before each query: call `CostTrackingService(self.db).check_budget(audit_id)`. If False, log warning and break (stop dispatching remaining queries)
- For each query: call `_dispatch_query_to_engines(query)`
- Return a `DispatchResult` dataclass with `total_queries`, `total_responses`, `total_failures`, `budget_exceeded` (bool)

**Method: `_dispatch_query_to_engines(self, query: AuditQuery) -> list[EngineResponse]`**
- Use `concurrent.futures.ThreadPoolExecutor(max_workers=settings.DISPATCH_MAX_WORKERS)`
- Submit `_call_engine(engine_name, config, query)` for each engine in ENGINE_CONFIG
- Use `as_completed(futures, timeout=settings.DISPATCH_TIMEOUT_SECONDS + 10)` to collect results
- For each completed future: on success, append result; on exception, create an EngineResponse with error_message set and response_text=""
- Return list of EngineResponse records (already persisted)

**Method: `_call_engine(self, engine_name: str, query: AuditQuery) -> EngineResponse`**
This runs in a ThreadPoolExecutor thread. Critical: each thread needs its own DB session and event loop.

Steps:
1. Get model name from settings: `model = getattr(settings, ENGINE_CONFIG[engine_name]["model_setting"])`
2. Build messages: `[{"role": "user", "content": query.query_text}]`
3. Create a new event loop for async cache/limiter calls: `loop = asyncio.new_event_loop()`
4. **Cache check**: `cached = loop.run_until_complete(cache.get(engine_name, model, messages, settings.DISPATCH_TEMPERATURE))`. If cached, create EngineResponse with cached=True, response_text from cached data, zero cost. Record zero-cost entry via CostTrackingService. Persist and return.
5. **Rate limiter acquire**: `loop.run_until_complete(get_provider_limiter(config["provider"]).acquire())`
6. **LLM call** in try/finally (finally releases rate limiter):
   ```python
   response = litellm.completion(
       model=model,
       messages=messages,
       temperature=settings.DISPATCH_TEMPERATURE,
   )
   ```
7. **Extract metadata**: response_text from `response.choices[0].message.content`, usage from `response.usage`, cost from `response._hidden_params.get("response_cost", 0.0)`, model_version from `response.model`
8. **Perplexity surcharge**: If engine is "perplexity", add `settings.PERPLEXITY_REQUEST_SURCHARGE` to cost
9. **Cache set**: Store response data in cache via `loop.run_until_complete(cache.set(...))`
10. **Cost tracking**: Use a thread-local DB session (create new SessionLocal()) to call `CostTrackingService(thread_db).record_cost(audit_id, engine_name, model_version, prompt_tokens, completion_tokens, Decimal(str(cost)))`
11. **Create and persist EngineResponse** record with all metadata
12. **Finally block**: release rate limiter via `loop.run_until_complete(limiter.release_async())` -- BUT the limiter.release() is sync, so just call `limiter.release()` directly. Close the event loop with `loop.close()`.

IMPORTANT implementation details:
- Each thread in ThreadPoolExecutor must create its OWN SQLAlchemy Session (SessionLocal()) because sessions are not thread-safe. The main dispatch_all_queries method uses self.db for budget checks and reading queries.
- Each thread creates its own asyncio event loop for cache and rate limiter calls. Close it in finally.
- The rate limiter's `release()` is sync (no await needed). Only `acquire()` is async.
- Use `from decimal import Decimal` for cost amounts -- follow existing CostTrackingService pattern.
- Validate that the API key for each engine is non-empty before attempting the call. If empty, create EngineResponse with error_message="API key not configured for {engine}" and skip the call. Check: OPENAI_API_KEY for openai, ANTHROPIC_API_KEY for anthropic, PERPLEXITYAI_API_KEY for perplexity.
- Log with loguru at each step: cache hit/miss, rate limiter acquired, LLM call start/complete, cost recorded, errors.
