    2. **Create backend/app/tasks/celery_app.py**: Configure the Celery application:
       ```python
       from celery import Celery
       from app.core.config import settings

       celery_app = Celery(
           "geo_platform",
           broker=settings.REDIS_URL,
           backend=settings.REDIS_URL,
       )

       celery_app.conf.update(
           task_serializer="json",
           accept_content=["json"],
           result_serializer="json",
           timezone="UTC",
           enable_utc=True,
           task_track_started=True,
           task_acks_late=True,
           worker_prefetch_multiplier=1,
           task_default_queue="geo_platform",
           task_routes={
               "app.tasks.audit.*": {"queue": "audit"},
               "app.tasks.analysis.*": {"queue": "analysis"},
           },
       )
       ```

       This configuration:
       - Uses Redis as both broker and result backend (already in docker-compose)
       - JSON serialization (safe, no pickle)
       - `task_acks_late=True` re-queues tasks if the worker crashes mid-execution
       - `worker_prefetch_multiplier=1` ensures fair task distribution
       - Route definitions prepare for Phase 2+ task organization
       - No actual tasks defined yet (those come in Phase 2+)

    3. **Verify docker-compose celery service**: The existing docker-compose.yml references `celery -A app.tasks.celery_app worker`. Confirm this import path matches the created module. If the celery service command is different, note it in the summary for future reference.
