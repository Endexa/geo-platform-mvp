  <name>Task 1: Create AI response cache service and outbound rate limiter</name>

  <action>
    1. **Create backend/app/services/cache_service.py**: Class `AICacheService`:
       - `__init__(self, redis_url: str | None = None)`: Creates `redis.asyncio.Redis.from_url(redis_url or settings.REDIS_URL)` connection. Store as `self.redis`.
       - `_make_key(self, engine: str, model: str, messages: list[dict], temperature: float) -> str`: Build deterministic cache key by JSON-serializing `{"engine": engine, "model": model, "messages": messages, "temperature": temperature}` with `sort_keys=True`, then SHA-256 hashing. Return `f"ai_cache:{hash_hex}"`.
       - `async get(self, engine: str, model: str, messages: list[dict], temperature: float = 0.0) -> dict | None`: Look up cache key. If found, `json.loads` and return. If not found or Redis error, return `None`. Catch `redis.RedisError` and log warning but return None (cache misses are acceptable on Redis outage).
       - `async set(self, engine: str, model: str, messages: list[dict], temperature: float, response: dict) -> None`: Store JSON-serialized response with `setex` using `settings.AI_CACHE_TTL_SECONDS` (default 86400 = 24h). Catch `redis.RedisError` and log warning (cache write failures are non-fatal).
       - `async get_stats(self) -> dict`: Return cache statistics -- `keys_count` from `self.redis.dbsize()`, useful for monitoring.
       - `async close(self)`: Close the Redis connection.

       **Critical design choice**: Cache reads/writes fail open (log and continue). A Redis outage should NOT prevent AI calls from working -- it just means no caching benefit. This is different from the outbound rate limiter which should fail closed.

    2. **Create backend/app/core/outbound_limiter.py**: Class `ProviderRateLimiter`:
       - `__init__(self, provider: str, rpm: int, max_concurrent: int)`:
         - `self.provider = provider`
         - `self.rpm = rpm`
         - `self.interval = 60.0 / rpm` (seconds between requests)
         - `self.semaphore = asyncio.Semaphore(max_concurrent)`
         - `self._last_request = 0.0`
         - `self._lock = asyncio.Lock()`
       - `async acquire(self)`: Acquire semaphore, then apply token bucket pacing:
         ```python
         await self.semaphore.acquire()
         async with self._lock:
             now = time.monotonic()
             wait_time = self._last_request + self.interval - now
             if wait_time > 0:
                 await asyncio.sleep(wait_time)
             self._last_request = time.monotonic()
         ```
       - `release(self)`: Release the semaphore.
       - `async __aenter__(self)`: Call `await self.acquire()`, return self.
       - `async __aexit__(self, *exc)`: Call `self.release()`.

       Then create a module-level registry and factory:
       ```python
       _limiters: dict[str, ProviderRateLimiter] = {}

       def get_provider_limiter(provider: str) -> ProviderRateLimiter:
           if provider not in _limiters:
               config = {
                   "openai": (settings.OPENAI_RPM, settings.OPENAI_MAX_CONCURRENT),
                   "anthropic": (settings.ANTHROPIC_RPM, settings.ANTHROPIC_MAX_CONCURRENT),
                   "perplexity": (settings.PERPLEXITY_RPM, settings.PERPLEXITY_MAX_CONCURRENT),
               }
               rpm, max_conc = config.get(provider, (60, 10))  # safe defaults
               _limiters[provider] = ProviderRateLimiter(provider, rpm, max_conc)
           return _limiters[provider]
       ```

       **Critical design choice**: The outbound rate limiter is in-process (asyncio primitives), not Redis-backed. This is intentional for Phase 1 -- it provides back-pressure within a single worker process. Multi-worker coordination can be added later if needed. The limiter does NOT fail open -- if you cannot acquire the semaphore, the caller blocks (back-pressure). If the caller times out, the request fails (which is correct -- we'd rather fail than exceed provider limits and get banned).
  </action>
