1. **Create backend/app/api/payments.py** with a new `router = APIRouter()`:

   a. **Pydantic schemas** (define at top of file or in a schemas section):
      - `CreateCheckoutRequest`: `price_id: str` (validated with Field pattern matching `^price_` prefix)
      - `CreateCheckoutResponse`: `checkout_url: str, session_id: str`
      - `PortalResponse`: `portal_url: str`
      - `SessionStatusResponse`: `status: str, subscription_id: Optional[str] = None, customer_email: Optional[str] = None`

   b. **POST /create-checkout** (authenticated, rate-limited via `integration_rate_limit`):
      - Depends on `get_current_active_user`, `get_db`
      - Instantiate `StripeService()`, call `create_checkout_session(request.price_id, current_user.email, str(current_user.id))`
      - Return `CreateCheckoutResponse` with `checkout_url` and `session_id`
      - Catch `stripe.StripeError` -> 502 "Payment service error"
      - Log checkout session creation with `loguru.logger`

   c. **POST /create-portal** (authenticated):
      - Query `Subscription` for current user -> get `stripe_customer_id`
      - If no subscription found, raise 404 "No active subscription"
      - Call `stripe_service.create_portal_session(sub.stripe_customer_id)`
      - Return `PortalResponse` with `portal_url`

   d. **GET /session-status** (authenticated, query param `session_id: str`):
      - Call `stripe_service.retrieve_checkout_session(session_id)`
      - Return `SessionStatusResponse` with session status, subscription ID, customer email
      - This is used by the success page to poll for subscription activation (handles webhook race condition per Pitfall 6 in research)

   e. **POST /webhook** (NO authentication -- public endpoint, secured via signature):
      - Read raw body: `payload = await request.body()`
      - Get `stripe-signature` header
      - Call `stripe_service.verify_webhook(payload.decode(), sig_header)` to verify + parse
      - **Idempotency check**: Query `WebhookEvent` by `stripe_event_id`. If exists, return `{"status": "already_processed"}` immediately.
      - **Store event** before processing: Create `WebhookEvent(stripe_event_id=event.id, event_type=event.type, status="received")`, add + commit.
      - **Handle events by type** (use a dict or if/elif chain):
        - `checkout.session.completed`: Extract `user_id` from `metadata`, `customer` ID, `subscription` ID from session. Upsert into `Subscription` table (create if not exists, update if exists). Set tier="pro", status="active".
        - `customer.subscription.updated`: Retrieve subscription by `stripe_subscription_id`. If not found, create it (upsert pattern -- handles out-of-order delivery per Pitfall 1). Update `status`, `current_period_end`, `cancel_at_period_end` from event data.
        - `customer.subscription.deleted`: Find subscription by `stripe_subscription_id`, set status="canceled".
        - `invoice.paid`: Find subscription by customer ID, confirm status="active".
        - `invoice.payment_failed`: Find subscription by customer ID, set status="past_due" (per Pitfall 5 in research).
      - After processing, update `webhook_event.status = "processed"`, commit.
      - On processing error, update `webhook_event.status = "failed"`, log error, but still return 200 (so Stripe doesn't retry for logic errors).
      - Catch `stripe.StripeError` on signature verification -> 400 "Invalid signature"
      - Catch `ValueError` on payload parse -> 400 "Invalid payload"
