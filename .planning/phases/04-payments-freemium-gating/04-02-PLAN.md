  <action>
1. **Create backend/app/core/dependencies.py** with:

   a. `SubscriptionTier(IntEnum)`: `FREE = 0`, `PRO = 1`. Only two tiers for v2 (per research recommendation). Import from `enum`.

   b. `async def get_user_tier(current_user, db) -> SubscriptionTier`: Query `Subscription` table for the user (`Subscription.user_id == current_user.id` AND `Subscription.status.in_(["active", "trialing"])`). If found, return `SubscriptionTier.PRO`. If not found, return `SubscriptionTier.FREE`. This is a **non-blocking** helper -- it returns the tier without raising errors.

   c. `def require_tier(minimum: SubscriptionTier)`: Factory function returning a FastAPI dependency. The inner dependency calls `get_user_tier()`. If the user's tier is below `minimum`, raises `HTTPException(status_code=402, detail=f"This feature requires a {minimum.name.lower()} subscription")`. Returns the tier if sufficient. Import `Depends`, `HTTPException`, `status` from `fastapi`, `Profile` from `app.models`, `get_current_active_user` from `app.core.security`, `get_db` from `app.core.database`, `Subscription` from `app.models.subscription`.

2. **Modify backend/app/api/audit.py** -- the audit detail endpoint (GET endpoint that returns a single audit's data):
   - Import `get_user_tier`, `SubscriptionTier` from `app.core.dependencies`
   - In the audit detail endpoint handler, call `get_user_tier(current_user, db)` to determine tier (do NOT use `require_tier` here -- free users should still access the endpoint, just with filtered data per PAY-03).
   - If tier is FREE, build a **filtered response**:
     - Include: `optimization_score` (overall), `crawlability` category scores (all criterion results where category="crawlability"), top 3 recommendations (ordered by impact/severity, limited to 3), basic audit metadata (url, status, created_at).
     - Exclude: Content Structure, Structured Data, Authority category scores. Exclude recommendations beyond the first 3.
     - Add a field `is_limited: bool = True` and `upgrade_prompt: str = "Upgrade to Pro to see all categories and recommendations"` to the response so the frontend knows to show upgrade prompts.
     - Add `total_recommendations: int` so the frontend can show "3 of 17 recommendations" as a teaser.
   - If tier is PRO, return the **full response** as-is with `is_limited: bool = False`.
   - **Critical**: The audit pipeline always runs ALL scorers regardless of tier (gating is at read time, not write time -- per research Open Question 4). Only the response is filtered.

3. **Modify backend/app/api/recommendations.py** -- the full recommendations list endpoint:
   - Add `Depends(require_tier(SubscriptionTier.PRO))` to the endpoint that returns all recommendations for an audit. Free users get top 3 via the audit detail endpoint; the dedicated recommendations endpoint is fully gated.
   - This means hitting GET /recommendations/{audit_id} without a pro subscription returns 402.

**Important notes:**
- Do NOT modify the existing `OrganizationChecker` in security.py. The new `require_tier` coexists alongside it. OrganizationChecker can be deprecated later.
- The tier check queries the `Subscription` model created in Plan 01 (NOT `Organization.subscription_tier`).
- Audit detail filtering must happen at the Python/Pydantic level, not SQL level. Fetch full data, then filter before returning.
