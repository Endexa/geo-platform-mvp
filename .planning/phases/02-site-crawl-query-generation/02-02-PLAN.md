**QueryGeneratorService:**

2. Create `backend/app/services/query_generator.py`:

   - Import: `litellm.completion`, `pydantic.BaseModel`, `pydantic.Field`, `typing.Literal`, `loguru.logger`, and settings from `app.core.config`

   - Define Pydantic models for structured output:
     ```python
     class GeneratedQuery(BaseModel):
         category: Literal["industry", "brand_direct", "comparison", "problem", "recommendation"]
         query_text: str = Field(description="Natural language query a user would ask an AI engine")
         intent: str = Field(description="What this query tests about brand visibility")

     class GeneratedQuerySet(BaseModel):
         queries: list[GeneratedQuery] = Field(
             min_length=8,  # Allow some flexibility (target 10-15, minimum 8)
             max_length=15,
             description="10-15 categorized queries for AI brand visibility audit"
         )
     ```

   - Define `SYSTEM_PROMPT` as a class attribute or module constant -- use the prompt from the research document (Pattern 4) with the following rules:
     - 5 categories: industry, brand_direct, comparison, problem, recommendation
     - Queries must sound like natural user questions, not keyword strings
     - Include the brand name ONLY in brand_direct queries
     - Other categories should be phrased so the brand COULD appear without being asked about
     - Cover diverse aspects of the brand's offerings
     - Distribution: ~2-3 per category for 10-15 total

   - Create `class QueryGeneratorService`:

     a. `def generate(self, crawl_data: dict, brand_name: str) -> GeneratedQuerySet`:
        - Build a user prompt from crawl data using `_build_prompt()`
        - Call `litellm.completion()` with:
          - `model=settings.QUERY_GEN_MODEL`
          - `messages=[{"role": "system", "content": SYSTEM_PROMPT}, {"role": "user", "content": user_prompt}]`
          - `response_format=GeneratedQuerySet`
          - `temperature=settings.QUERY_GEN_TEMPERATURE`
        - Parse response: `GeneratedQuerySet.model_validate_json(response.choices[0].message.content)`
        - Log query count and category distribution at info level
        - If fewer than 10 queries generated, log warning but do NOT retry (costly)
        - Wrap entire LLM call in try/except -- on failure, log error and re-raise with descriptive message

     b. `def _build_prompt(self, crawl_data: dict, brand_name: str) -> str`:
        - Build a structured prompt with sections:
          - Brand name
          - Domain
          - Industry signals (from crawl_data)
          - Page title and meta description
          - Schema.org types found (from JSON-LD)
          - Open Graph data
          - Top keywords (from crawl_data["content_keywords"])
          - Main content (truncated -- already truncated in CrawlResult but enforce limit here too)
        - Format as clear sections for the LLM to understand the brand context
        - Total prompt should be informative but not bloated

     c. `def extract_brand_name(self, crawl_data: dict) -> str`:
        - Follow the pattern from research (Brand Name Extraction):
          1. Priority 1: schema.org Organization name from `schema_org` list
          2. Priority 2: `og:site_name` from `open_graph` dict
          3. Priority 3: Title tag -- first segment before common separators (` | `, ` - `, ` :: `, ` -- `)
          4. Fallback: domain name from `crawl_data["domain"]`
        - This is a public method because the Celery task needs it

   Note: `litellm.completion()` is synchronous by default -- no async issues in Celery. Use it directly (not `acompletion`).

**Celery task:**

1. Create `backend/app/tasks/audit_tasks.py`:

   - Import: `celery_app` from `app.tasks.celery_app`, `asyncio`, `loguru.logger`, `SessionLocal` from `app.core.database`, models from `app.models`, services from `app.services`

   - Define `@celery_app.task(bind=True, name="app.tasks.audit.run_crawl_and_generate", max_retries=1, default_retry_delay=30)`:
     ```python
     def run_crawl_and_generate(self, audit_id: str, url: str):
     ```

   - Implementation:
     a. Create a DB session using `SessionLocal()` (NOT async -- Celery workers are sync)
     b. Fetch the Audit record by ID
     c. Set status to `AuditStatus.CRAWLING`, commit
     d. **Step 1: Crawl** -- Create `CrawlerService()`, call `asyncio.run(crawler.crawl(url))` to run the async crawl in sync context. Store `crawl_result.model_dump()` in `audit.crawl_data`. Commit.
     e. Set status to `AuditStatus.GENERATING_QUERIES`, commit
     f. **Step 2: Extract brand name** -- Call `query_gen.extract_brand_name(audit.crawl_data)`
     g. **Step 3: Generate queries** -- Create `QueryGeneratorService()`, call `query_gen.generate(audit.crawl_data, brand_name)`. This is synchronous (litellm.completion is sync).
     h. **Step 4: Store queries** -- For each query in the result, create `AuditQuery(audit_id=audit_id, category=q.category, query_text=q.query_text, sort_order=i)`, add to session. Commit.
     i. Set status to `AuditStatus.GENERATING_QUERIES` (ready for Phase 3 to pick up -- or `COMPLETED` if there's no Phase 3 yet? Use `GENERATING_QUERIES` as the terminal state for Phase 2, since Phase 3 will update to `DISPATCHING`). Actually -- per the research, after query generation the status should indicate completion of this phase. Set to `AuditStatus.COMPLETED` for now so the API shows it as done. Phase 3 will change the flow to continue to DISPATCHING.
     j. Set `audit.completed_at` to current UTC time if setting to COMPLETED
     k. On any exception: set `audit.status = AuditStatus.FAILED`, `audit.error_message = str(e)`, commit, then re-raise
     l. Always close the DB session in a `finally` block

   - Add task route: The task is named `app.tasks.audit.run_crawl_and_generate` which matches the existing route `"app.tasks.audit.*": {"queue": "audit"}` in celery_app.py. No changes needed to celery_app.py.

**API endpoint:**

2. Create `backend/app/api/audit.py`:

   - Import: `APIRouter`, `Depends`, `HTTPException`, `status` from fastapi; `Session` from sqlalchemy.orm; `get_db` from `app.core.database`; `get_current_active_user` from `app.core.security`; `Profile` from `app.models`; `Audit`, `AuditStatus` from `app.models.audit`; `AuditCreate`, `AuditResponse`, `AuditDetailResponse` from `app.schemas.audit`; `run_crawl_and_generate` from `app.tasks.audit_tasks`; `urlparse` from `urllib.parse`; `uuid`

   - Create router: `router = APIRouter(prefix="/audit", tags=["audit"])`

   - `POST /` -- Create and trigger a new audit:
     ```python
     @router.post("/", response_model=AuditResponse, status_code=status.HTTP_202_ACCEPTED)
     def create_audit(
         request: AuditCreate,
         db: Session = Depends(get_db),
         current_user: Profile = Depends(get_current_active_user),
     ):
     ```
     - Validate URL: parse with urlparse, ensure scheme is http or https, ensure netloc is non-empty. Raise 422 if invalid.
     - Extract domain from URL
     - Create `Audit(user_id=current_user.id, url=request.url, domain=domain, status=AuditStatus.PENDING)`
     - Add to DB, commit, refresh
     - Dispatch Celery task: `run_crawl_and_generate.delay(str(audit.id), request.url)`
     - Return the audit record (202 Accepted -- async processing)

   - `GET /{audit_id}` -- Get audit status and details:
     ```python
     @router.get("/{audit_id}", response_model=AuditDetailResponse)
     def get_audit(
         audit_id: str,
         db: Session = Depends(get_db),
         current_user: Profile = Depends(get_current_active_user),
     ):
     ```
     - Fetch Audit by ID with eager-load of queries
     - Verify `audit.user_id == current_user.id` (users can only see their own audits). Raise 404 if not found or not owned.
     - Return audit with queries

   - `GET /` -- List user's audits:
     ```python
     @router.get("/", response_model=list[AuditResponse])
     def list_audits(
         db: Session = Depends(get_db),
         current_user: Profile = Depends(get_current_active_user),
         limit: int = 20,
         offset: int = 0,
     ):
     ```
     - Query Audit where `user_id == current_user.id`, ordered by `created_at` desc, with limit/offset
     - Return list of audits (without crawl_data for efficiency)

   All three endpoints use `Depends(get_current_active_user)` for auth enforcement (following Phase 1 pattern).
