1. Install `@microsoft/fetch-event-source`: run `cd frontend && npm install @microsoft/fetch-event-source`.

2. Create `frontend/composables/useChat.ts`:
   - Export function `useChat(auditId: Ref<string>)` returning `{ messages, streamingContent, isStreaming, error, sendMessage, stopStreaming, loadHistory }`
   - `messages`: `ref<Array<{ role: 'user' | 'assistant'; content: string; timestamp: string }>>([])` -- full conversation history
   - `streamingContent`: `ref('')` -- partial assistant response being streamed
   - `isStreaming`: `ref(false)` -- whether currently receiving tokens
   - `error`: `ref<string | null>(null)` -- error message
   - `abortController`: `ref<AbortController | null>(null)` -- for canceling SSE connection

   - `getToken()`: read access_token from cookie (same pattern as useApiFetch.ts -- `document.cookie.match(/(?:^|;\s*)access_token=([^;]*)/)`)

   - `async loadHistory()`: call `useApiFetch<{ messages: ..., audit_id: string }>(`/chat/${auditId.value}/history`)`, set messages.value from response. Catch errors silently (no history yet is fine).

   - `async sendMessage(content: string)`:
     * Guard: return early if isStreaming.value or content is empty/whitespace
     * Push user message to messages.value immediately (optimistic UI)
     * Reset error, streamingContent, set isStreaming=true, create new AbortController
     * Use `fetchEventSource` from `@microsoft/fetch-event-source`:
       - URL: `${config.public.apiUrl}/api/v1/chat/${auditId.value}/chat`
       - method: 'POST'
       - headers: Content-Type application/json + Authorization Bearer token (if token exists)
       - body: JSON.stringify({ message: content.trim() })
       - signal: abortController.value.signal
       - `onmessage(ev)`: parse ev.data as JSON. If `data.token` -> append to streamingContent. If `data.done` -> push complete assistant message to messages array, clear streamingContent, set isStreaming=false. If `data.error` -> set error.value, set isStreaming=false.
       - `onerror(err)`: set error to "Connection lost. Please try again.", set isStreaming=false, throw err to stop retrying
     * Wrap in try/catch: if AbortError, ignore (user stopped). Otherwise set error.value.

   - `stopStreaming()`: abort the controller, if streamingContent has content push it as assistant message with "[Response stopped]" suffix, clear streamingContent, set isStreaming=false.

3. Create `frontend/components/ChatPanel.vue`:
   - Props: `auditId: string`, `isOpen: boolean` (controls visibility)
   - Emits: `close`
   - Uses `useChat(computed(() => props.auditId))` composable
   - On mount (watch isOpen becoming true): call `loadHistory()`

   Template structure (slide-over panel from right side):
   - Overlay backdrop (semi-transparent, click to close)
   - Panel container: fixed right-0, w-96 (or w-[28rem]), full height, white bg, shadow-xl, z-40
   - Header: "Ask about your audit" title + close button (X icon from Heroicons)
   - Message list (scrollable, flex-col, gap-3):
     * For each message in messages: display bubble. User messages right-aligned (bg-blue-100), assistant messages left-aligned (bg-gray-50)
     * Render assistant message content as markdown. Use a simple approach: split by newlines, handle **bold**, `code`, bullet points. OR if a markdown library is too heavy, render as plain text with `whitespace-pre-wrap` -- this is acceptable for v1.
     * If isStreaming and streamingContent: show a "typing" assistant bubble with streamingContent + blinking cursor indicator
   - Auto-scroll to bottom when new messages arrive or streaming content updates (use `nextTick` + `scrollIntoView`)
   - Input area at bottom: text input (or textarea for multi-line) + send button
     * Disable send button while isStreaming
     * Submit on Enter (not Shift+Enter for textarea)
     * Placeholder: "Ask about your audit results..."
   - Error display: if error is set, show red banner above input
   - Empty state: if no messages, show helper text like "Ask me anything about your audit. For example: 'Why is my schema score low?' or 'What should I fix first?'"

   Design system compliance:
   - Use Fira Code for headings, Fira Sans for body (per MASTER.md design system)
   - Primary blue (#1E40AF) for user messages, slate-50 for assistant messages
   - All clickable elements have `cursor-pointer`
   - Focus rings on input and buttons: `focus-visible:ring-2 focus-visible:ring-blue-500`
   - Transition on panel open/close: `transition-transform duration-200` (not exceeding 300ms cap)
   - No emoji icons -- use Heroicons for close (XMarkIcon), send (PaperAirplaneIcon)
   - z-index: use z-40 for panel (below modals at z-50, per design system z-scale)

   - Add `<ChatPanel v-if="auditId && isCompleted" :audit-id="auditId" :is-open="chatOpen" @close="chatOpen = false" />` at the bottom of the template.

   The button and ChatPanel should only render when audit is completed.
