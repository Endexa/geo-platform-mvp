This doesn't invalidate any requirement (all score correctly for the pages they process) but limits the real-world value of per-page scoring.

### Integration Issues

#### BROKEN-02: Multi-Page Link Discovery (Degraded)
- **File:** `backend/app/services/scoring/scoring_orchestrator.py:84`
- **Issue:** `crawl_data.get("main_content", "")` returns plain text (not HTML). BeautifulSoup finds zero `<a>` tags. Internal link discovery always returns empty.
- **Impact:** Only homepage is scored per audit. READY-01 through READY-06 work correctly on the homepage but don't extend to internal pages. Competitor scoring (COMP-04) inherits the same limitation.
- **Fix:** Store raw HTML in CrawlResult and use it for link discovery.

#### BROKEN-01: PDF Template Path (Environment)
- **File:** `backend/app/services/dashboard_service.py:313`
- **Issue:** `FileSystemLoader("app/templates")` uses relative path.
- **Impact:** Works in Docker (CWD=backend/) but may fail in other environments.
- **Fix:** Use `pathlib.Path(__file__).parent.parent / "templates"`.

#### MISS-01: Frontend Auth Middleware Gap (Cosmetic)
- **Files:** `dashboard.vue`, `brands.vue`, `settings.vue`, `analyze.vue`, `index.vue`
- **Issue:** These pages use layout-level `onMounted` auth guard instead of route `middleware: ['auth']`. Users briefly see page skeleton before redirect.
- **Impact:** No security vulnerability (API returns 401 regardless). UX issue only.
- **Fix:** Add `middleware: ['auth']` to `definePageMeta` in all 5 pages.
